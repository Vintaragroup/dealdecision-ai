# PR36.5 — Truthfulness Hardening Across Investor Insights

**Status:** Complete  
**Typecheck:** ✅ Clean

## Objective

This PR is **not a feature PR**. It is a correctness PR.

Goal: prevent bad facts (OCR fragments, spreadsheet leakage, malformed numerics,
volume metrics misread as raise amounts, and single-source LLM hallucinations)
from reaching investor-facing outputs.

---

## Changes by Phase

### Phase 4 — Volume Metric Taint Guard (`resolve-raise-amount.ts`)

**Problem:** "cars financed £100M" extracted as raise amount for Carmoola-class decks.
Loan book, GMV, annual budget, and other traction/scale metrics were matching the
same `£/$/€ + number` pattern as genuine raise amounts.

**Fix:**
- New `RejectReason`: `"volume_metric_taint"`
- New export: `VOLUME_NOT_RAISE_RE` — regex covering `cars financed`, `car[s] on finance`,
  `GMV`, `loan book`, `loan volume`, `originations`, `capital deployed`, `annual budget`,
  `debt facility`, `booked volume`, `total facilitated/processed`, etc.
- New export: `isCandidateTaintedByVolumeMetric(context: string): boolean`
- Rule 2c in `resolveRaiseAmount()`: reject when volume metric taint AND no strong raise verb
- Guard also wired into `detectRaiseAllMatchesForConflict()` in `stage-2-deterministic.ts`

**Exemption:** If `hasStrongRaiseSignal()` is also present (e.g. "We are raising £3M.  
To date we have financed 5,000 cars."), the candidate is NOT rejected.

---

### Phase 3 — Numeric Sanity Validation (`numeric-sanity-v1.ts`)

**Problem:** Malformed currency strings (`$000`, `£0.00`) and absurd percentages
(`2350.0%` from OCR scale errors, `0%` from placeholder cells) bypass validation.

**Fix:** New module with:
- `NUMERIC_SANITY_REASON` const: `INVALID_MALFORMED_CURRENCY`, `INVALID_PERCENT_SCALE`,
  `ZERO_PERCENT_PLACEHOLDER`
- `isMalformedCurrency(value)` — detects zero-value/placeholder currency strings
- `isPercentScaleError(value)` — detects values ≥ 1000% (OCR scale errors)
- `isZeroPercentPlaceholder(value)` — detects `0%`, `0.0%` placeholder values
- `validateNumericValue(value)` — composite gate, first rejection wins

---

### Phase 1 — Text Candidate Quality Gate (`text-candidate-quality-v1.ts`)

**Problem:** Product/market fallback resolution was promoting spreadsheet tab text
(`FY2024E Revenue Assumptions`), mid-sentence OCR continuations (`and help scale
the go-to-market engine`), and garbled noun-lists.

**Fix:** New module with:
- `TEXT_QUALITY_REASON` const: `SPREADSHEET_FRAGMENT`, `OCR_CONTINUATION_FRAGMENT`,
  `INCOHERENT_TEXT`
- `isSpreadsheetFragment(text)` — detects FY notation, `£000s`, month column headers,
  financial model keywords (assumptions:, headcount plan, opex, etc.) and column
  header runs (4+ title-case words without a verb)
- `isOcrContinuationFragment(text)` — detects continuation conjunctions at sentence
  start and lowercase-first fragments
- `isIncoherentText(text)` — detects 3+ commas without a main verb (noun-list garbling)
- `checkTextCandidateQuality(candidate)` — composite gate

---

### Phase 5 — Quality Gate Integration (`deterministic-slot-fallback-v1.ts`)

**Fix:**
- `resolveProductFallbackV1()` `tryMatch()`: calls `checkTextCandidateQuality()` and
  rejects on `!accept` — full gate (spreadsheet + continuation + incoherent)
- `resolveMarketFallbackV1()` `tryMatch()`: uses `isSpreadsheetFragment()` +
  `isIncoherentText()` directly — **OCR continuation SKIPPED** intentionally, because
  ICP target phrases extracted by pattern regex groups naturally start lowercase
  (e.g. "mid-market healthcare companies...") and must not be treated as continuation
  fragments

### Phase 6 — Signal Extraction Confidence Gating (`signal-extraction.ts`)

**Problem:** A single external result (one TechCrunch headline) could cause a
"competitive_intensity: high" or "direction: growing" signal to fire, driven by
LLM-style term extraction from a single source.

**Fix:**
- `BUCKET_MIN_CONFIDENCE_RESULTS` map: minimum result count per bucket before
  drawing confident conclusions (default 2; `external_risks` = 1)
- `hasSufficientConfidence(results, bucketKey)` helper
- `extractCompetitiveLandscapeSignal`: sparse gate returns hedged signal with
  `category_fragmentation: "unknown"`, `competitive_intensity: "unknown"`, empty
  name arrays, and `"Insufficient confidence..."` summary
- `extractMarketOutlookSignal`: sparse gate returns `direction: "unknown"` and
  `"Insufficient external data..."` summary
- `extractFounderTeamSignal`: sparse gate sets `limited_footprint: true` and
  hedged summary `"Limited public data available for X — only one external source found"`

**Pre-existing tests updated:** 3 tests in `external-diligence-v1.test.ts` that
used single results for `market_outlook` and `competitive_landscape` were updated
to use 2 results, preserving their original intent.

---

### Phase 7 — Product Category Corrections (`infer-product-category.ts`)

**Problem:** Carmoola, WebMax, and StackFactor were receiving generic category labels
(`"fintech"`, `"software"`) instead of specific ones because B2B generic patterns
fired first.

**Fix:** 5 new high-specificity entries added at the **top** of `SECTOR_CATEGORY_MAP`
(before B2B generic patterns):

| Pattern | Category | Regression fix for |
|---|---|---|
| `car finance`, `auto lending/finance`, `vehicle finance`, `motor finance` | `"car finance technology"` | Carmoola |
| `mortgage SaaS/software/platform`, `digital mortgage`, `lending workflow`, `mortgage origination` | `"digital mortgage software"` | WebMax |
| `talent intelligence`, `skills intelligence/mapping`, `workforce analytics`, `skills gap` | `"talent intelligence platform"` | StackFactor |
| `consumer lending/loan`, `personal loan`, `instalment credit`, `BNPL` | `"consumer lending technology"` | — |
| `embedded finance`, `open banking`, `BaaS`, `fintech-as-a-service`, `API-first finance` | `"embedded finance platform"` | — |

## Reason Code Reference

### `RejectReason` (raise amount)
| Code | Condition |
|---|---|
| `market_context_taint` | Pre-existing: number appears next to TAM/market-size language |
| `fund_aum_context` | Pre-existing: number appears next to fund AUM language |
| `volume_metric_taint` | **New (Phase 4):** number appears in volume/traction metric context |
| `magnitude_no_strong_verb` | Pre-existing: large number without raise verb |

| Code | Condition |
|---|---|
| `INVALID_MALFORMED_CURRENCY` | `$000`, `£0.00`, `€000`, `$-` etc. |
| `INVALID_PERCENT_SCALE` | ≥ 1000% (OCR scale error) |
| `ZERO_PERCENT_PLACEHOLDER` | `0%`, `0.0%` (template placeholder) |

| `OCR_CONTINUATION_FRAGMENT` | Continuation conjunction, lowercase-first fragment |
| `INCOHERENT_TEXT` | 3+ commas without a main verb |

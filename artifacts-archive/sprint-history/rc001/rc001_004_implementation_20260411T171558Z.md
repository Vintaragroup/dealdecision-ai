## RC-001 — SEC Filing Classifier

### Problem
`detectDocTypeHints()` in `document-intelligence.ts` did not recognize SEC filings (S-1, 10-K, 10-Q). NerdWallet's actual S-1 prospectus was classified as `pitch_deck` with no SEC-specific tag, masking its IPO-stage nature.

### Change
**File:** `packages/core/src/services/document-intelligence/document-intelligence.ts`

Added four new `addIf()` calls inside `detectDocTypeHints()`:

```typescript
addIf("sec_filing_s1", /\bform\s+s-?1\b|\bregistration\s+statement\b/i, 0.95, "sec_keyword");
addIf("sec_filing_10k", /\bform\s+10-?k\b|\bannual\s+report\s+pursuant\s+to\s+section\s+13\b/i, 0.95, "sec_keyword");
addIf("sec_filing_10q", /\bform\s+10-?q\b|\bquarterly\s+report\s+pursuant\s+to\s+section\s+13\b/i, 0.95, "sec_keyword");
addIf("regulatory_filing", /\bsecurities\s+and\s+exchange\s+commission\b|\bsec\.gov\b/i, 0.85, "sec_keyword");
```

These emit evidence items with tags `["signal:doc_type_hint", "doc_type:<hint>"]` into the `evidence_items` table at extraction time.

### Tests
`packages/core/src/services/document-intelligence/__tests__/document-intelligence.test.ts`
- `RC-001: detects FORM S-1 and emits sec_filing_s1 doc_type hint`
- `RC-001: detects FORM 10-K and emits sec_filing_10k doc_type hint`
- `RC-001: detects FORM 10-Q and emits sec_filing_10q doc_type hint`
- `RC-001: regular pitch deck does NOT emit SEC filing hints`

## RC-002 — Going Concern Detection

### Problem
No mechanism existed to detect "going concern" language in SEC filings. WeWork's 10-K (`we-20221231.pdf`) contains "substantial doubt as to the Company's ability to continue as a going concern" — a critical risk signal that was completely invisible to the pipeline.

### Change
**File:** `packages/core/src/services/document-intelligence/document-intelligence.ts`

Added going concern detector just before `items.sort()` in `buildEvidenceItemsForBlocks()`:

```typescript
const GOING_CONCERN_RE = /substantial\s+doubt.*(?:going\s+concern|ability\s+to\s+continue)|going\s+concern.*substantial\s+doubt|ability\s+to\s+continue\s+as\s+a\s+going\s+concern/i;
if (GOING_CONCERN_RE.test(allText)) {
  items.push({
    evidence_id: `gc_${Date.now()}`,
    source_type: "document_intelligence_signal",
    source_path: "doc:going_concern_detection",
    tags: ["signal:going_concern", "risk:going_concern"],
    confidence: 0.95,
    content_text: "going_concern",
    content_json: { detected: true },
    meta: {},
  });
}
```

### DB Verification
```sql
-- WeWork we-20221231.pdf confirmed match:
full_text ~* 'substantial\s+doubt.*going\s+concern|ability\s+to\s+continue\s+as\s+a\s+going\s+concern'
→ going_concern_match
```

### Known Gap (RC-002b — deferred)
The `risk:going_concern` evidence item is stored in `evidence_items` but is **not yet promoted to `report.redFlags`**. A follow-up task (RC-002b) should add a report compiler step reading `risk:going_concern` evidence items and appending:
```json
{ "severity": "high", "message": "Going concern doubt noted in SEC filing", "action": "Verify cash position and management remediation plan" }
```

### Tests
- `RC-002: detects 'substantial doubt ... going concern'`
- `RC-002: 'going concern' variant phrase detected`
- `RC-002: normal financials without going concern language emit no risk:going_concern`

## RC-003 — Revenue Hallucination Hardening

### Problem
KPI tile extraction in `extract-kpi-tile-claims.ts` was treating market-size numbers (TAM/SAM/SOM) mentioned on pitch deck slides as revenue figures. Nanochon's pre-seed deck has "Total Addressable Market: $2B" — which could be miscategorized as ARR or revenue if the slide also shows a dollar figure.

### Change
**File:** `apps/worker/src/lib/financial-facts/extract-kpi-tile-claims.ts`

Expanded `MARKET_PROJECTION_RE` from:
```typescript
/\bper\s+(?:sam|som|tam)\b|%\s*of\s+(?:tam|sam|som)\b|\bsam\s+arr\b|.../i
```
to also catch:
```typescript
|\b(?:total\s+)?addressable\s+market\b
|\bmarket\s+(?:size|opportunity)\b
|\b(?:tam|sam|som)\s*[:\-]\s*\$
|\brev(?:enue)?\s+opportunity\b
```

Only applied to `MARKET_PROJECTION_SENSITIVE_KEYS` = `Set(["arr", "mrr", "revenue", "gtv", "gmv"])`.

### DB Verification
```sql
-- Nanochon confirmed match:
full_text ~* 'addressable\s+market|market\s+(size|opportunity)|tam.*\$|sam.*\$'
→ market_size_match
```

### Tests
`apps/worker/src/lib/financial-facts/__tests__/extract-kpi-tile-claims.test.ts` (114 total, 9 RC-003)
- Rejects "addressable market", "total addressable market", "market opportunity", "market size", "TAM: $15B", "SAM: $3B", "revenue opportunity" for revenue/ARR/MRR keys
- Does NOT suppress clean ARR/MRR values without market-size context

## RC-004 — Funding Stage Expansion

### Problem
`FundingStageModelV1` only had `pre_seed | seed | series_a | growth | unknown`. NerdWallet (IPO-stage S-1 filer) and WeWork (public company filing 10-K) were both being misclassified — NerdWallet as `pre_seed` (from "IDEA" phase label), WeWork as `unknown` (conflicting signals).

### Changes

**File 1:** `packages/core/src/models/funding-stage-model.ts`
- Added `"ipo" | "public_company"` to `FundingStageModelV1` type union
- Added `doc_type_hints?: string[] | null` parameter to `inferFundingStageModelV1`
- **Priority-ordered early exits** (10-K/10-Q checked BEFORE S-1 — annual filers are already public):
  ```typescript
  // 10-K/10-Q wins over S-1 if both are present
  if (hints.some((h) => h === 'sec_filing_10k' || h === 'sec_filing_10q')) {
    return { funding_stage: 'public_company', confidence: 0.9, ... };
  }
  if (hints.some((h) => h === 'sec_filing_s1')) {
    return { funding_stage: 'ipo', confidence: 0.9, ... };
  }
  ```
- `ClassicFundingStage` local type introduced to fix TypeScript fan-out in score normalization
- `stageScores` typed as `Record<Exclude<FundingStage, "unknown" | "ipo" | "public_company">, number>`

**File 2:** `packages/core/src/reports/compiler-simple.ts`  
Two call sites wired with hint extraction from DIO claim text:
```typescript
// RC-004: extract doc type hints from DIO claim text
// The DIO data lives in dio.dio.phase1.claims[*].{text, evidence[*].snippet}
const claims: any[] = (dio as any)?.dio?.phase1?.claims ?? [];
// ... collect all claim text + snippets ...
if (/\bform\s+s-?1\b|\bregistration\s+statement\b/i.test(allText)) hints.push('sec_filing_s1');
if (/\bform\s+10-?k\b|\bannual\s+report\s+pursuant\s+to\s+section\s+13\b/i.test(allText)) hints.push('sec_filing_10k');
if (/\bform\s+10-?q\b|\bquarterly\s+report\s+pursuant\s+to\s+section\s+13\b/i.test(allText)) hints.push('sec_filing_10q');
```

**Note:** Initial implementation attempted to read hints from `dio.inputs.evidence`. This path was empty — the DIO structure is `{ dio: { phase1: { claims: [...] } } }`. Fixed to read from claim text/snippets directly, which IS populated with document content.

**File 3:** `packages/core/src/scoring/stage-weight-matrix.ts`
- Expanded `getStageWeightMatrix` signature to accept `"ipo" | "public_company"`
- Added weight matrix for both (mirrors `growth` — financial-heavy profile)

## Implementation Notes & Gotchas

1. **DIO evidence path was wrong**: Initial RC-004 read `dio.inputs.evidence` — which is always empty. The actual DIO structure is `{ dio: { phase1: { claims: [{ text, evidence: [{ snippet }] }] } } }`. Fixed to extract claim text from the correct path.

2. **10-K > S-1 priority**: 10-K annual reports often contain references to past registration statements, which would trigger the S-1 pattern. Fixed by checking 10-K BEFORE S-1 — if both are present, `public_company` wins.

3. **RC-002 is evidence-only**: Going concern is stored as `risk:going_concern` in `evidence_items` but NOT yet promoted to `report.redFlags`. RC-002b should add that compiler step.

4. **RC-003 is extraction-time only**: The `MARKET_PROJECTION_RE` guard runs at KPI extraction (worker). Already-extracted financial_facts in the DB are not retroactively corrected on pipeline re-run unless the document is re-extracted.

5. **TypeScript `ClassicFundingStage`**: The score normalization functions (`softmax01`, `getStageWeightMatrix`, `inferStageFromRaiseAmountBand`) only operate on the classic 4-stage set. A local type alias prevents TypeScript from widening to include `ipo`/`public_company` in contexts where they have no meaning.
